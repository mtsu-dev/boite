# Boite 2.0.0-beta.1

Built on 2026-09-08 from `main`. One Windows x64 installer,
`Boite_2.0.0-beta.1_x64-setup.exe`, per user, no elevation. It is the first
build intended for regular use. The behavior, support and checks below describe
that dated build; current behavior is documented in the topic guides.

## What boite is

The Bun core runs agents through their protocols. Desktop and phone clients
connect over authenticated WebSocket. In this build, an idle thread holds a
journal row; an active turn starts its CLI and releases it after completion.

## What is inside

### The core

- JSON-RPC over WebSocket with a token and an origin check, every method and
  event typed in `packages/contracts`.
- A SQLite journal: every message, part, permission, question and setting is an
  event, and a client that reconnects replays what it missed.
- A scheduler with a global cap and a per account cap, so fifty prompts sent at
  once run six at a time and the rest queue in order.
- The trace on Windows: one Job Object per thread nested under `boite-agents`,
  exact start and exit events from a completion port, real load per thread, a
  CPU hard cap and a per thread memory cap from settings, kill tree on stop.
- The focus guard: a window opened by any process a thread launched is pushed
  behind the one you were on, and the focus comes back. The audio mute: the same
  processes are muted in the Windows mixer while they live. Both on by default,
  both switchable under General settings.
- Crash recovery: a core killed mid turn marks the turn as an error on the next
  start, with a reason that says to send the prompt again, and no thread stays
  stuck.
- `listenOnLan` in General settings decides the bind on the next start.

### The agents

| Provider | Protocol | Login | Models |
|---|---|---|---|
| Claude | the Claude Agent SDK over the Claude CLI | the CLI's own, or `claude auth login` per isolated account | from the descriptor, with an effort scale per model |
| OpenCode | ACP over `opencode acp` | `opencode auth login` | read from the agent (534 on 2026-09-08) |
| Antigravity | ACP over Google's `agy_acp_server`, installed by Boite | the protocol's own sign-in, a Google link | read from the agent |
| Codex | the Codex app-server protocol over `codex app-server` | `codex login --device-auth` | read from the agent, an effort scale per model |
| pi | pi's rpc mode over `pi --mode rpc` | none from Boite, pi's own `/login` | read from the agent, one id per provider |

Every provider is a JSON descriptor, shipped or dropped by the user under the
data directory, and a wrong one is refused with the file, the field and what was
expected. Accounts beyond the default one are isolated: their own home, their own
login, blind to each other. Antigravity has no default account at all, every
account is isolated, and its binary is downloaded by Boite from Google's release
with a sha256 and every file's size checked.

Permissions, questions and reasoning are parts of the message: a permission
request draws a card with allow and deny, an agent's free form question draws
its options, the model's reasoning folds under the answer.

### The window

- Chat first: a draft thread opens on `Ctrl+N` and is created on the first send,
  titled from the prompt. Provider, account, model, effort and permission mode in
  one picker; the model list comes from the agent for the ones that own it.
- A sidebar grouped by project with the live threads first, a search, context
  menus, drag to width, `Ctrl+B` to fold.
- A right panel of surfaces per thread, in T3 Code's shape: a tab strip over the
  trace and any number of browser tabs. The browser tab is a real page in the
  desktop app, a child webview the shell parks over the panel, with back,
  forward, reload, an address field, zoom on `Ctrl+=`, `Ctrl+-` and `Ctrl+0`,
  and http, https and about as the only schemes it will open. A page that asks
  for a window of its own becomes another tab.
- The composer: Enter sends, `Ctrl+Enter` sends and opens the next draft on the
  same choice, `ArrowUp` recalls this thread's sent prompts, `Ctrl+S` stashes
  what is written and brings it back on an empty box.
- Long threads render a window of the timeline past sixty messages, so a four
  hundred message thread scrolls at the same cost as a short one.
- Settings with a left nav: General (caps, warm process minutes, LAN, focus
  guard, mute), Appearance (system, dark, light), Accounts, Providers.
- A frameless window with its own title bar, a tray icon, close hides to the
  tray and Quit in the tray menu quits.

### The phone

Turn `listenOnLan` on, restart, open the pairing link the core prints on a phone
on the same network. The UI installs as a web app with a service worker, so it
opens even while the core is down, and every RPC frame carries the token from
the link. A sign-in that ends on a loopback redirect on the desktop is finished
by pasting the redirect URL into the Accounts page, which the core fetches
once.

## Installing

Run the installer. It puts `boite-shell.exe`, the `boite-core.exe` sidecar, the
two worker files and the UI under `%LOCALAPPDATA%\Boite`, and it installs beside
a version 1, never over it. The first run asks for a project folder, from the
native picker or by dropping one on the window. The data directory is
`%LOCALAPPDATA%\boite2` unless `BOITE_DATA_DIR` says otherwise.

The default account of Claude, OpenCode, Codex and pi is the login you already
have in that CLI: nothing to do. Antigravity shows Install first, then a sign-in
link on the Accounts page.

## What runs on your own login, and only if you ask

The test suite runs on a temporary data directory and an echo agent that never
reaches the network. The live tests and one bench row use a real login and
spend a few tokens, each behind its own variable: `BOITE_E2E_CLAUDE`,
`BOITE_E2E_OPENCODE`, `BOITE_E2E_CODEX`, `BOITE_E2E_PI`, `BOITE_E2E_ANTIGRAVITY`
(which opens a Google sign-in in your browser) and `BOITE_BENCH_CLAUDE`.
`BOITE_E2E_ANTIGRAVITY_INSTALL` downloads Google's 468 MB release without
signing in. One more, `BOITE_E2E_GUARD`, opens a window and takes the focus for
a blink to prove the guard. [development.md](../internals/development.md) lists them.

## Known gaps

- Windows only. The trace on Linux and macOS polls a process group and reports
  direct children; there is no installer for either yet.
- No plugin host: the accounts plugin of Boite 1 has no home here yet.
- The browser surface has been proved by its commands and its CDP targets, not
  by a person looking at it: title changes, a page opening a window and the zoom
  never ran on a visible window.
- No worktree per thread, no attachments, no slash commands or mentions, no
  checkpoints, no notifications, no command palette, no keybindings file.
- A pairing link carries the core token itself. A short lived grant exchanged for
  a session is the next step.
- Quit is immediate from the tray; there is no hold on `Ctrl+Q` yet, and threads
  cannot be pinned.
- The `unstable` feature of the tauri crate is what the browser surface builds
  on, and a minor tauri release can change its shape.

## Resources

Measured on 2026-09-08 with `bun run bench` and `bun run bench/idle-rss.ts`,
Windows x64, 16 logical cores, Bun 1.4.2, against the Boite Legacy app that was
running on the same machine with two Claude terminals open. The complete [dated table and methods](../../bench/results/2026-09-08.md)
record the comparison limits.

| Metric | boite | Boite Legacy |
|---|---|---|
| Core cold start to the first HTTP answer | 61 ms | 91 ms |
| Core idle working set | 42.0 MB (47.5 MB as the compiled exe) | 15.1 MB |
| Cost of one idle thread | none measurable (a journal row) | 14.1 MB (a PTY, a cmd.exe, a conhost.exe) |
| 100 idle threads, core working set delta | 0.8 MB | not comparable |
| 50 echo turns at cap 6, wall time | 7.6 s | no equivalent |
| 50 echo turns at cap 50, wall time | 1.0 s | no equivalent |
| 50 echo turns at cap 50, first delta median | 23 ms | no equivalent |
| Desktop app, spawn to a core answering | 761 ms | not launched |
| Desktop app idle, shell process | 27.4 MB | 89.3 MB |
| Desktop app idle, WebView2 (six processes each) | 334.8 MB | 732.7 MB |
| Desktop app idle, everything it owns | 419.4 MB | 2599.2 MB |
| Agent CLIs held while nothing runs | 0 | 1749.0 MB (two claude.exe) |
| One real Claude turn, peak claude.exe | 288.3 MB (2026-09-05) | 874.5 MB per live claude.exe |

The core against bare Bun, median of three:

| Process | Working set |
|---|---|
| bare `bun` | 25.4 MB |

agent SDKs loading on the first turn instead of at start.
